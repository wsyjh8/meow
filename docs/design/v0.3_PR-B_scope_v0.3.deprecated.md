## 1. 变体 C 关键语义

### 1.1 启动序列

```
冷启动:
  1. WordbookLoader 读 assets/words/{book}.json → 写 drift example_sentences
     （现有 bundled 路径，永远跑，不删）
  2. ContentPackageService.syncIfNeeded() 异步触发（PR-B4 后默认开）:
     a. GET /api/v1/content/manifest?since_release=last_release_id
     b. 对每个 package: server contentVersion > 本地 → 下载 + 解压 + install
     c. install 用 InsertOrReplace 覆盖 drift 现有行
  3. UI 渲染（不阻塞，bundled 数据已就绪）
```

### 1.2 数据冲突解决

**manifest 永远赢 bundled**：
- bundled 是 APK 打包时刻的快照（落后于 server）
- manifest 是 server 当前权威
- 同 stable_id 冲突时，manifest 数据覆盖 bundled 数据

**例子**：APK 打包时 `examples-zk@v3` 是最新；用户半年后装 App，server 已经发到 `examples-zk@v8`。
- bundled 写 v3 数据 → drift
- manifest sync 拉 v8 → install 覆盖
- 用户看到 v8

### 1.3 网络场景

| 场景 | bundled 行为 | manifest 行为 | 用户感受 |
|---|---|---|---|
| 全程在线 | 启动写 drift（一闪即过）| 异步覆盖更新 | 看到最新数据 |
| 启动有网，后续断网 | 同上 | 已 sync 一次 | 看到上次 sync 的版本 |
| 全程离线 | 启动写 drift | sync 失败（静默）| 看到 bundled 版本（半年前快照）|
| 首启离线（新装）| 启动写 drift | 失败 | 看到 bundled 版本 |

**核心：永远不挂死**——bundled 是底，manifest 是覆盖层。

## 4. PR-B3 — feature flag 默认关 ≈ 2 天

**目标**：WordbookLoader 加 if/else 分支，flag 控制走 manifest 增量更新还是不跑。bundled 路径**永远跑**。

### 4.1 范围（变体 C 调整版）

- `WordbookLoader.loadIfNeeded()` 写 drift bundled 数据**保持不变**
- 之后加分支：
  - flag=true → 异步触发 `ContentPackageService.syncIfNeeded()`（不阻塞 UI）
  - flag=false（默认）→ 不跑 sync
- flag 通过 `local_settings` 表控制（debug 用 / 设置页可切）
- 关 flag regression：bundled 行为完全等同 PR-B2 之前

### 4.2 与变体 A PR-C 区别

变体 A 的 PR-C 把 WordbookLoader 改成"flag → ContentPackageService.syncIfNeeded() / else → bundled"——是两条互斥分支。
变体 C 改成"bundled 永远跑 + flag → 异步追加 sync"——是顺序叠加。

bundled 永远跑这个事不是 flag 的责任，是架构本身。

### 4.3 完成条件

1. 开 flag 跑一次 → manifest sync 流程通畅，drift 看到 bundle + manifest 数据合并
2. 关 flag 跑一次 → 与 PR-B2 之前完全一样（regression）
3. 任何用户首启都不会出问题

## 5. PR-B4 — flag 默认开 + 接入启动 ≈ 1 天

**目标**：flag 默认开，让所有用户的启动序列里加上 manifest sync。

### 5.1 范围（变体 C 简化版）

- flag 默认 true（`local_settings.use_manifest_sync = true` initial）
- main.dart 启动序列：
  - 不变：LocalDatabase → AppDatabase → WordbookLoader×3 → EnrichmentBootstrap → runApp
  - 加：runApp 之前 / 之后异步触发 `ContentPackageService.syncIfNeeded()`（5s 超时 fallback，与 EnrichmentBootstrap 一致风格）
- 加错误状态展示：sync 失败时 toast / log（不阻塞用户）
- 手动刷新入口（设置页"检查内容更新"按钮）

### 5.2 与变体 A PR-D 区别

变体 A PR-D：删 5.6MB bundle + 加 600KB minimum-set + 改 WordbookLoader 默认走 manifest（2 天）
变体 C PR-B4：bundle 不动 + 不做 minimum-set + 仅打开 flag + 接入启动（1 天）

工作量差距来自不做 minimum-set 生成 + 不删 bundle + 不改 WordbookLoader 默认路径。

### 5.3 完成条件

1. flag 默认开后，启动会跑 manifest sync（log 验证）
2. 离线启动仍能用（bundled 兜底；sync 失败静默）
3. 在线启动几秒内 drift 看到 manifest 数据覆盖（user-visible 行为：例句更新即时反映）
4. APK 大小**不变**（5.6MB），不减不增
5. 既有用户升级时本地 SQLite 数据保留
