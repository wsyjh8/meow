## 1. 变体 C 关键语义（v0.4 收口版）

### 1.1 启动序列（D1 收口后）

```
冷启动:
  1. WordbookLoader 读 assets/words/{book}.json → 写 drift example_sentences
     - 启动时检查 content_package_state 有 examples-{book} 记录:
       - 有 (PR-B3+ 用户) → INSERT IGNORE，bundle 不覆盖 manifest 已写的 stable_id
       - 无 (新装 / PR-B2 之前老用户) → 现有清表重导路径
  2. ContentPackageService.syncIfNeeded() 异步触发（PR-B4 后默认开）:
     a. GET /api/v1/content/manifest（不传 since_release，每次全量；D4）
     b. set diff: 本地 vs server，决定 install/upgrade/skip
     c. install: gzip 解压 → drift InsertOrReplace（同 stable_id 覆盖；D5 不删）
     d. UPSERT content_package_state（同 transaction）
  3. UI 渲染（不阻塞，bundled 数据已就绪）
```

### 1.2 数据冲突解决（D5 收口）

**优先级**：manifest 覆盖 bundled 同 stable_id；**v0.3 不做 server 端删除**。

- 同 stable_id：manifest 数据覆盖（InsertOrReplace）
- server 删除的 stable_id：客户端**保留**（v0.3 不实现 tombstone）
- 操作员真要删某条：调 SQL `UPDATE examples SET status='deleted'`，客户端 PR-C 加 status 路径才会响应

### 1.3 网络场景（含 D1 收口）

| 场景 | bundled 行为 | manifest 行为 | 用户感受 |
|---|---|---|---|
| 全程在线 | 启动写 drift（INSERT IGNORE，已有 manifest 数据保留）| 异步覆盖更新 | 看到最新数据 |
| 启动有网，后续断网 | 同上 | 已 sync 一次 | 看到上次 sync 的版本 |
| 全程离线 | 启动 INSERT IGNORE 写 bundle 数据 | sync 失败（静默）| 看到 manifest + bundle 合并版本 |
| 首启离线（新装）| 清表写 bundle（content_package_state 空）| 失败 | 看到 bundle 版本 |
| **app 升级 + 离线**（D1 关键场景）| INSERT IGNORE，**已有 manifest 数据保留** | 失败 | **不丢数据**（D1 收口前会丢）|

## 4. PR-B3 — feature flag + WordbookLoader 改 + server staging serve ≈ 2.5 天

**目标**：开启 manifest 消费路径，加 feature flag 灰度保护，**改 WordbookLoader 解决 D1 升级丢数据问题**，**加 server staging serve 解决 D3 URL 问题**。

### 4.1 范围（v0.4 扩大版）

#### 4.1.1 server 端 staging serve（0.5 天，D3 收口）

- NestJS 加 static route 暴露 `apps/api/audio-pipeline-staging/` 为 `/cdn/staging/...`
- 或更直接：manifest API 返回前把 `file:///abs/path/audio-pipeline-staging/{file}` 转换为 `http://{host}/cdn/staging/{file}`
- production 仍跳过 file://（PR-A controller.ts:171 行为保留）

#### 4.1.2 mobile feature flag（0.5 天）

- 用 SharedPreferences（不建 drift 表，依赖 R1#2 修正）
- key: `manifest_sync_enabled`，default false
- 设置页加开关（debug 用）

#### 4.1.3 WordbookLoader 改（1 天，D1 收口）

- 启动时查 `content_package_state` 表是否有 `examples-{book}` 记录：
  - **有**：跳过清表，对每个 stable_id 用 `InsertMode.insertOrIgnore`（manifest 数据保留）
  - **无**：现有清表重导路径不变（PR-B2 之前老用户 + 新装首启）
- 启动后异步触发 `ContentPackageService.syncIfNeeded()`（条件：feature flag = true）
- 关 flag regression：bundled 行为完全等同 PR-B2 之前

#### 4.1.4 完成条件

1. 开 flag + 在线启动 → manifest sync 完整跑通，drift 见到 bundle + manifest 合并数据
2. 关 flag → bundled 行为不变（regression test）
3. **D1 关键测试**：模拟"装 v3 → manifest 写 v8 → 升级到 v4 → 关网启动"，验证 v8 数据保留
4. server staging serve route 跑通：HTTP GET `/cdn/staging/examples-zk@v1.jsonl.gz` 返 200 + 正确 content
5. dev mode manifest API 返 http:// URL；production 仍跳 file://

5. 既有用户升级时本地 SQLite 数据保留

bundle 永驻，无 fallback 可清。feature flag 是否长期保留**由后续具体观测决定**：

清理触发条件（同时满足）：
- PR-B4 merge **30 天 +**
- crash rate 不上升
- **manifest_sync 失败率 < 1%**（需埋点；留 PR-C 观测性才有数据）
- **flag toggle 关闭路径 0 流量**（实际无人切回；需 SharedPreferences value 分布统计，PR-C）
- 0 个用户报"内容更新失败 / 数据消失"反馈

如以上全部满足才单独开轻量 PR 删 flag + 清相关分支。**v0.3.0 主线发布不依赖此 PR**。

## 附录 A：术语对照表

| 术语 | 定义 |
|---|---|
| release | content_release 行，治理 SSOT |
| package | content_manifest 行，物理包文件元数据 |
| package_set | release.package_set 数组 |
| dual-condition | release.status='active' AND manifest.is_active=true |
| revoke | 硬撤回（不可逆，**不可被 rollback 恢复**） |
| deprecate | 软下线（**唯一可被 rollback 恢复的状态**） |
| rollback | `deprecated → active`（PR-B1） |
| orphan | FS 有文件 / PG 无对应行（PR-B1 orphan-scan） |
| stale | PG 有行 + status='eligible_for_gc'（PR-A gc-stale） |
| **bundled** | 打包进 APK 的 5.4MB JSON（assets/words/*.json），变体 C 永驻 |
| **content_package_state** | drift 表（PR-B2 新加 12 列），追踪 mobile 已 imported 的 package release_id / version / book_id / compression 等 |
| **feature flag** | PR-B3 加，SharedPreferences 存储；PR-B4 默认开；PR-B5（候选）删 |
| **staging serve** | PR-B3 server 端 NestJS static route，把 file:// 转 http:// 让 mobile HTTP GET 能下载 |
