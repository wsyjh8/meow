## 0. 一句话结论

长期推荐把内容结构升级为：

```txt
words
books
word_book_memberships
examples
example_book_memberships
audio_assets
content_manifest
content_package_state
audio_file_cache
```

核心原则：

> **单词是全局资产，词书是内容集合，词书和单词靠 membership 表连接；例句是独立内容资产，必要时再用 membership 表控制不同词书展示哪些例句；例句文本走 content package 分发，例句音频走 audio_assets + CDN + 本地缓存。**

---

## 1. 当前问题

当前已经暴露出两个长期问题。

### 1.1 词 / 词书 / 例句关系需要更标准

用户提出的设计方向是：

1. 所有单词汇集到同一个表。
2. 单词书单独一个表。
3. 单词书记录自己有哪些单词。
4. example 单独一个表。

这个方向是对的，但需要工程化修正：

- 不要在 `books` 表里直接存 `word_ids_json`。
- 应该用 `word_book_memberships` 中间表表达“某本词书包含哪些单词”。
- 例句也不要塞进 `words` 表。
- 例句应单独成表，并通过 stable_id 支持音频、收藏、缓存、后续更新。
- 如果不同词书希望展示不同难度或不同顺序的例句，需要增加 `example_book_memberships`。

### 1.2 例句文本和例句音频发布节奏不一致

当前实际问题：

- 例句文本现在来自 bundled JSON，修改文本需要重新 build APK / 发布 App。
- 例句音频已经可以通过远端拉取、缓存、播放。
- 这导致“文本更新慢，音频更新快”的结构不对称。
- 后续继续加例句和音频时，bundle 进 APK 会越来越重，内容维护会越来越不方便。

长期应该改成：

```txt
例句文本：
PG examples → content_manifest → examples package on CDN → local SQLite mirror → LearningPage

例句音频：
PG audio_assets → /examples/:stable_id/audio → CDN mp3 → audio_file_cache
```

## 2. 设计目标

### 2.1 长期目标

1. 支持所有单词全局唯一管理。
2. 支持一本词书包含多个单词。
3. 支持同一个单词属于多本词书。
4. 支持一个单词拥有多条例句。
5. 支持同一条例句复用到多本词书。
6. 支持不同词书对同一个单词展示不同例句。
7. 支持例句发音远端拉取与本地缓存。
8. 支持例句文本不发版即可更新。
9. 支持内容包版本、校验、回滚、失败重试。
10. 不改变 FSRS、奖励、结算、今日目标、Session valid 等主机制事实 owner。

### 2.2 当前不做

本方案不要求立即完成以下内容：

1. 不做学习页每个单词实时请求例句 API。
2. 不做复杂 per-user example recommendation。
3. 不做 A/B 例句实验。
4. 不做义项级 FSRS。
5. 不做用户状态全面云端同步。
6. 不做完整内容运营后台。
7. 不把例句或音频失败写成学习失败。
8. 不改变 Review / Study 的 rating、FSRS、奖励、结算链路。

## 3. 核心表结构设计

## 3.1 `words` — 全局单词表

### 作用

保存全局唯一单词主档。

### 推荐字段

```txt
words
- id                VARCHAR(64) PK
- word_text          VARCHAR(200) NOT NULL
- phonetic_us        VARCHAR(64)
- phonetic_uk        VARCHAR(64)
- pos_summary        VARCHAR(64)
- frequency_rank     INT DEFAULT 0
- created_at         TIMESTAMPTZ
- updated_at         TIMESTAMPTZ
```

### 规则

1. 一个单词只在 `words` 中出现一次。
2. 多本词书共享同一个 `word_id`。
3. `words.id` 长期应采用稳定规范键，例如 normalized lowercase key。
4. 需要补充正式 normalization algorithm：
   - trim
   - lowercase
   - punctuation normalization
   - hyphen / apostrophe handling
   - Polish / polish 等消歧例外

### 为什么这样设计

如果 `abandon` 同时出现在 CET4、IELTS、高考词书中，`words` 只保留一行。这样音标、发音、近反义词、词根词缀、例句都能复用，避免重复数据和维护成本。

---

## 3.2 `books` — 词书表

### 作用

保存词书本身，不直接保存词列表。

### 推荐字段

```txt
books
- id                VARCHAR(32) PK
- display_name      VARCHAR(100) NOT NULL
- description       TEXT
- total_words       INT DEFAULT 0
- content_version   VARCHAR(32)
- sort_order        INT DEFAULT 0
- is_active         BOOLEAN DEFAULT TRUE
- created_at        TIMESTAMPTZ
- updated_at        TIMESTAMPTZ
```

### 规则

1. 一本词书只在 `books` 中出现一次。
2. `books` 不存 `word_ids_json`。
3. `books.content_version` 是这本词书当前聚合内容版本指针。
4. 具体包下载与校验应由 `content_manifest` 控制。

---

## 3.3 `word_book_memberships` — 单词与词书关系表

### 作用

表达“某个单词属于某本词书”。

### 推荐字段

```txt
word_book_memberships
- word_id           VARCHAR(64) FK -> words.id
- book_id           VARCHAR(32) FK -> books.id
- sort_order        INT DEFAULT 0
- source_key        VARCHAR(64)
- unit_no           VARCHAR(32) NULL
- lesson_no         VARCHAR(32) NULL
- is_required       BOOLEAN DEFAULT TRUE
- status            active / hidden / deprecated
- created_at
- updated_at

PK(word_id, book_id)
```

### 规则

1. 一个词可以属于多本词书。
2. 一本词书可以有多个词。
3. 某个词在某本书里的顺序写在这张表。
4. 删除某本词书中的某个词时，不删除 `words`，只删除或 deprecated 对应 membership。
5. 改某本词书顺序时，只改 membership 的 `sort_order`。

### 查询示例

```sql
SELECT w.*
FROM words w
JOIN word_book_memberships wbm
  ON wbm.word_id = w.id
WHERE wbm.book_id = :book_id
  AND wbm.status = 'active'
ORDER BY wbm.sort_order;
```

---

## 3.4 `examples` — 例句表

### 作用

保存例句文本。例句是独立内容资产，不直接塞进 `words`。

### 推荐字段

```txt
examples
- stable_id          VARCHAR(32) PK / UNIQUE
- word_id            VARCHAR(64) FK -> words.id
- sense_id           VARCHAR(80) NULL
- sense_label        TEXT NULL
- en                 TEXT NOT NULL
- cn                 TEXT NOT NULL
- difficulty         VARCHAR(32) NULL
- source             VARCHAR(64) NULL
- generator          VARCHAR(64) NULL
- status             active / deprecated / deleted
- content_hash       VARCHAR(64)
- created_at
- updated_at
```

### 规则

1. 一个单词可以有多条例句。
2. 新代码必须引用 `stable_id`，不要依赖自增 ID。
3. 英文例句内容发生实质变化时，应生成新的 stable_id。
4. 旧 stable_id 不要立刻硬删，应先 deprecated，给旧客户端和音频缓存过渡期。
5. `sense_id` 可以为空，`sense_label` 用于当前兼容。
6. `word_senses` 未来引入后，`examples.sense_id` 再逐步补齐。

### stable_id 建议

```txt
stable_id = hash(word_id + normalized_en)
```

建议补充：

- normalized_en 的规则
- hash 长度
- 冲突处理策略
- 是否带 prefix，例如 `ex_`

---

## 3.5 `example_book_memberships` — 例句与词书关系表

### 作用

表达“某条例句在某本词书中展示”。

这是我建议新增的长期表。

### 为什么需要这张表

同一个单词在不同词书中，可能需要不同难度的例句：

```txt
abandon in 高考：简单例句
abandon in CET4：中等例句
abandon in IELTS：更长、更学术的例句
```

如果例句只挂 `word_id`，所有词书看到的例句都一样。长期不够灵活。

### 推荐字段

```txt
example_book_memberships
- example_id        VARCHAR(32) FK -> examples.stable_id
- book_id           VARCHAR(32) FK -> books.id
- sort_order        INT DEFAULT 0
- is_primary        BOOLEAN DEFAULT FALSE
- min_level         VARCHAR(32) NULL
- max_level         VARCHAR(32) NULL
- status            active / hidden / deprecated
- created_at
- updated_at

PK(example_id, book_id)
```

### 查询示例

```sql
SELECT e.*
FROM examples e
JOIN example_book_memberships ebm
  ON ebm.example_id = e.stable_id
WHERE e.word_id = :word_id
  AND ebm.book_id = :book_id
  AND ebm.status = 'active'
  AND e.status = 'active'
ORDER BY ebm.sort_order;
```

### MVP 是否必须

- MVP 可以暂时不做。
- 但从长期结构看，建议现在在 target architecture 中设计进去。
- 第一版可以只简单使用：每条例句属于当前词书，后续再扩展复用。

---

## 3.6 `audio_assets` — 音频资源表

### 作用

统一管理单词音频和例句音频。

### 推荐字段

```txt
audio_assets
- id                 VARCHAR(32) PK
- target_kind         word / example
- target_id           word_id / example stable_id
- locale              en-US / en-GB
- voice               af_bella / ...
- format              mp3 / opus / aac
- audio_version       VARCHAR(32)
- url                 TEXT
- checksum_sha256     VARCHAR(64)
- bytes               INT
- duration_ms         INT
- status              ready / missing / failed / deprecated
- source              tts_provider / cloud_generated / human_recorded
- tts_provider        VARCHAR(64) NULL
- tts_model           VARCHAR(64) NULL
- created_at
- updated_at
```

### 规则

1. `audio_assets` 管远端音频元数据，不存实际音频 blob。
2. 实际音频文件存对象存储 / CDN。
3. App 不自己算 audio_id。
4. App 不自己拼 CDN URL。
5. App 通过 API 获取 `{ audio_id, url, checksum, duration_ms, status }`。
6. 本地缓存通过 `audio_file_cache` 管理。
7. 音频更新时通过 `audio_version` / checksum 判断本地缓存是否失效。

---

## 3.7 `content_manifest` — 内容包清单表

### 作用

控制静态内容包的下载、校验、版本、激活与回滚。

### 推荐字段

```txt
content_manifest
- id                   VARCHAR(128) PK
- package_kind          wordbook_core / examples / enrichment / audio_metadata
- package_name          examples-zk / examples-gk / wordbook-zk
- book_id               VARCHAR(32) NULL
- locale                VARCHAR(16) NULL
- content_version       VARCHAR(32)
- file_url              TEXT NOT NULL
- checksum_sha256       VARCHAR(64) NOT NULL
- size_bytes            INT
- compression           gzip / none
- min_app_version       VARCHAR(32)
- status                active / deprecated / revoked
- generated_at
- activated_at
- expires_at            NULL
- supersedes_id         NULL
```

### 规则

1. `content_manifest` 是客户端下载内容包的唯一入口。
2. App 不直接猜 CDN 路径。
3. App 不只靠 `books.content_version` 判断下载。
4. `books.content_version` 可作为快速指针；`content_manifest` 才是具体下载和校验入口。
5. CDN 静态包必须带 checksum。
6. manifest 必须支持 deprecated / revoked，方便回滚。

---

## 3.8 `content_package_state` — 本地内容包状态表

### 作用

记录 App 本地已下载 / 已导入的内容包状态。

### 推荐字段

```txt
content_package_state
- package_id
- package_kind
- book_id
- content_version
- checksum_sha256
- local_path
- status               pending / downloaded / verified / imported / failed
- imported_at
- last_checked_at
- last_error
```

### 规则

1. 不要只靠 SharedPreferences 记录“导入过版本 4”。
2. 每个内容包的下载、校验、导入、失败原因都要可追踪。
3. 支持失败重试。
4. 支持以后按 book 更新。
5. 支持清理旧包和回滚。

---

## 3.9 `audio_file_cache` — 本地音频缓存表

### 作用

记录音频文件在设备文件系统中的缓存状态。

### 推荐字段

```txt
audio_file_cache
- audio_id             VARCHAR(32) PK
- target_kind           word / example
- target_id             word_id / example stable_id
- local_path            TEXT NOT NULL
- checksum_sha256       VARCHAR(64)
- bytes                 INT
- cached_at             TIMESTAMP
- last_played_at        TIMESTAMP
- status                cached / missing / corrupted / expired
```

### 规则

1. mp3 / opus / aac 文件放文件系统。
2. SQLite 只存 metadata 和本地路径。
3. 不把音频文件存 SQLite blob。
4. LRU 清理看 `last_played_at` / bytes。
5. checksum 不匹配时重新下载。

## 5. App 运行时读取策略

### 5.1 学习页读取例句

学习页不直接请求网络获取例句文本。

推荐流程：

```txt
LearningPage
→ current word_id + active book_id
→ local SQLite 查询 examples / example_book_memberships
→ 有例句则展示
→ 无例句则隐藏例句模块
```

### 5.2 例句包缺失时

如果 examples package 下载失败：

1. 学习流程不能阻断。
2. 例句模块可以隐藏。
3. 可以使用 bundled fallback examples。
4. UI 不显示大错误弹窗。
5. 不影响 FSRS、奖励、结算、今日目标。

### 5.3 例句音频播放

推荐流程：

```txt
用户点击例句喇叭
→ App 查本地 audio_file_cache
→ 命中且 checksum 合法：播放本地文件
→ 未命中：GET /api/v1/examples/:stable_id/audio
→ 返回 audio_id/url/checksum
→ 流播或下载
→ 写 audio_file_cache
→ 播放
```

失败时：

1. 显示轻提示，例如“发音暂时不可用”。
2. 不阻断学习。
3. 不影响 rating。
4. 不影响 FSRS。
5. 不影响奖励、结算、今日目标。

## 7. 内容发布管线

当前不建议继续让多个脚本分散承担内容发布。建议收口成统一 pipeline 入口。

### 7.1 统一入口

```txt
apps/api/scripts/content_pipeline/pipeline.py
```

### 7.2 推荐子命令

```txt
build-examples-package
publish-example-audio
publish-word-audio
ingest-audio-assets
publish-manifest
gc-stale
validate
```

### 7.3 管线原则

1. LLM 生成例句和 TTS 生成音频不要强行做成单笔大事务。
2. 但“包生成 → manifest 发布 → stale GC”应有发布顺序。
3. 每个步骤必须支持 dry-run。
4. 每个包必须有 checksum。
5. stale GC 默认 dry-run。
6. 真实删除必须显式带 `--gc`。
7. 默认保留 grace window，例如 30 天，避免旧客户端请求旧资源失败。

---

## 8. Stale 资产清理规则

### 8.1 为什么需要

音频和例句更新后，旧音频文件可能继续堆积。已经观测到 stale MP3 堆积问题，因此需要设计 GC。

### 8.2 推荐规则

```txt
如果 audio_id 不在当前 active audio_assets 中
且不在 deprecated grace window 中
且文件最后访问时间超过 grace_days
则可以删除
```

### 8.3 默认策略

```txt
gc-stale --dry-run
gc-stale --gc --grace-days 30
```

### 8.4 不允许

1. 不允许按“当前表里没有”就立刻硬删。
2. 不允许无 dry-run 删除。
3. 不允许不记录删除报告。
4. 不允许删除 still-active / deprecated grace window 内资源。

## 9. 数据变更场景

### 9.1 新增一个单词

例如新增 `resilience`：

```txt
1. INSERT words
2. INSERT word_book_memberships if it belongs to a book
3. INSERT examples
4. INSERT example_book_memberships if examples are book-scoped
5. INSERT word_forms / word_relations / word_phrases / morpheme matches if available
6. Publish content package / manifest
```

### 9.2 某本词书新增一个已有单词

例如 `abandon` 加入 IELTS：

```txt
INSERT word_book_memberships(word_id='abandon', book_id='ielts', sort_order=...)
```

不复制 `words`。

### 9.3 某本词书删除一个单词

不要删除 `words`。

```txt
UPDATE word_book_memberships
SET status = 'deprecated'
WHERE word_id = 'abandon' AND book_id = 'ielts'
```

### 9.4 修改某个单词音标

```txt
UPDATE words
SET phonetic_us = ...
WHERE id = 'abandon'
```

### 9.5 修改某条例句文本

如果英文文本有实质变化：

```txt
1. 旧 examples.status = deprecated
2. 生成新的 stable_id
3. 插入新 examples
4. 更新 example_book_memberships 指向新例句
5. 旧音频进入 deprecated grace window
6. 新例句触发新音频生成
```

### 9.6 修改某条例句中文翻译

如果只改中文翻译，可以有两种策略：

#### 策略 A：stable_id 不变

适合把 stable_id 视为英文句子内容 ID。

```txt
UPDATE examples.cn
UPDATE content_hash
```

#### 策略 B：stable_id 变化

适合把 stable_id 视为双语内容 ID。

推荐本项目采用 **策略 A**：

> stable_id 主要绑定英文句子和音频；中文翻译改动不应该导致音频和收藏失效。

## 11. 边界规则

### 11.1 不改变主机制事实

本方案不改变：

```txt

reward_settlement_status
reward_ledger
settlements

today 聚合
```

### 11.2 内容缺失不等于学习失败

```txt
例句缺失 ≠ 学习失败
音频缺失 ≠ 学习失败
近反义词缺失 ≠ 学习失败
词根词缀缺失 ≠ 学习失败
```

### 11.3 App 运行时原则

```txt
LearningPage 读本地 SQLite
Audio 播放通过 audio_assets 远端定位 + 本地缓存
内容包通过 manifest 下载
不让学习页每个单词实时请求例句文本 API
```

### 11.4 文案边界

UI 不得说：

```txt
例句已同步完成
音频一定可用
所有内容已完整下载
```

可以说：

```txt
部分发音暂不可用
例句内容正在准备
无例句时隐藏模块
```
