# Claude Code 启动 Prompt

> **使用方法**：把下面整段（从「---」之间的内容）复制粘贴到 Claude Code 会话开头作为第一条消息。Claude Code 读完后会先给你一份计划，等你确认后再开始实现。

---

你将实现一个移动端背单词 App 的前端 UI。完整规格在同目录的 SPEC.md 里，分阶段的实现步骤在 TASKS.md 里。

## 第一步：阅读和确认

在动手写任何代码之前：

1. 读完 SPEC.md 整份文档（约 1300 行）。重点理解：
   - 第 2 节"设计原则"
   - 第 3 节"设计 Tokens"（所有精确的颜色、字号、圆角值）
   - 第 8 节"实现注意事项"，**特别是 8.8 节"不要做的事"**
   - 第 9 节"范围外内容"——明确哪些是不在你的工作范围里的

2. 读完 TASKS.md，理解 phase 的顺序和每个 phase 的产出。

3. 然后**用你自己的话总结**：
   - 你接下来要做什么
   - 你打算用什么技术栈（如果需要决定的话先问我）
   - 你识别到的最关键的设计纪律
   - 你打算如何处理"原版 tab"（这是个特殊的 tab，不是要你重新设计的）

把总结发给我，等我确认后再开始 Phase 1。**不要在我确认之前写任何代码或创建任何文件**。

## 工作纪律（最重要的几条）

### 1. 严格按 TASKS.md 的 phase 顺序执行
一次完成一个 phase。每个 phase 完成后**停下来等我 review**，不要为了"效率"跳到下一个 phase。不要合并 phase。

### 2. 不要漂移
SPEC.md 第 8.8 节列出的"不要做的事"是有意的克制，不是疏忽。即使你觉得加一个阴影、加一个动画、加一个 hover 效果、把字重 500 改成 600 会"更好看"，**也不要加**。所有这些克制都有底层依据，记录在 SPEC 附录 B 里。

如果在某一处你**强烈感觉**应该违反规则，停下来告诉我你想违反哪一条以及为什么，让我决定。**不要静默地"优化"任何东西**。

### 3. 遇到 SPEC 第 9 节的"范围外内容"必须停下来问
具体包括但不限于：
- 词书页、学习流程页
- Mochi 子页（换装、房间、零食柜、日记、相册）
- 个人资料编辑页
- 错词本详情页

在路由层面这些是**死链接**或**未实现状态**。**不要自己创建占位页**，也不要"先写一个 Coming Soon 页面"。给我一个明确的"这一项需要你确认怎么处理"的暂停。

### 4. SPEC 没规定的细节也要停下来问
具体例如：
- 用什么技术栈（React Native？Flutter？Web？Vue？React？）
- 文件结构怎么组织
- 状态管理用什么
- 是否需要单元测试

不要默认决定。不同的技术栈下整个项目结构会差很多，必须先问我。

### 5. 每个页面实现完成后做自我 review
按 SPEC 第 10 节的"验收标准"逐项检查：
- 像素级（颜色 hex、圆角、字号是否完全一致）
- 行为（点击、跳转、动态状态）
- 设计纪律（有没有偷偷加阴影、渐变、800 字重等）
- 萌度（整体感觉对不对）

把 self-review 的结果写出来告诉我，再让我看实际效果。

## 关于"原版"tab 的特殊说明

tab bar 现在有 6 个 tab，**不是 5 个**。第 6 个 tab "原版" 是一个特殊存在：

- 它指向项目代码库里**已经存在的旧版首页代码**
- 你的工作**不包括**重写、重构、修改、美化这部分代码
- 你只需要把它作为一个 tab 路由暴露出来，让用户能从底部 tab 点到它
- 视觉上它必须和其他 5 个 tab **明显区分**（详见 SPEC 第 5.1.6 节）

**如果你在代码库里找不到这个旧首页**，停下来告诉我，**不要自己创建一个占位页**。我会告诉你它在哪里或者怎么处理。
